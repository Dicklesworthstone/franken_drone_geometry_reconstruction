# Algorithm Portfolio and Certification Doctrine

FDGR is algorithmically ambitious but semantically conservative. Every optimized or learned algorithm has a deterministic reference, explicit policy, bounded resource contract, certificate, and refusal behavior.

## 1. Geometry and estimation

The portfolio includes deterministic keyframe selection, feature and track formation, robust two-view estimation, rotation averaging, translation/scale synchronization, pose-graph optimization, bundle adjustment, incremental marginalization, depth/normal fusion, surfel and TSDF integration, occupancy and free-space carving, meshing, topology repair, registration, uncertainty propagation, and held-out-view validation.

Each execution records basis, numeric policy, stopping rule, residual distributions, outliers, conditioning, operation counts, output digest, and any bounded nondeterminism.

## 2. Graph algorithms

Anchor-pinned projections support:

- connected components and dynamic connectivity;
- articulation points, bridges, blocks, and cut trees;
- SCCs, condensation DAGs, topological order, dominators;
- shortest/k-shortest paths and temporal reachability;
- max-flow/min-cut, Gomory–Hu, min-cost flow, matching;
- spanning forests, cycle bases, core/truss/community structure;
- PageRank, HITS, PPR, centrality, spectral diagnostics;
- graph edit/difference and branch merge witnesses;
- treewidth/elimination heuristics;
- submodular/set-cover/orienteering algorithms for active perception and context selection.

Uses include pose connectivity, fragile topology, room/portal inference, utility relations, visibility, capture routing, question sharing, provenance, obligation critical paths, and multi-agent conflicts.

## 3. Progressive algorithms

Fast initial candidates may be refined by better geometry, graph, search, or model stages. Every stage is individually useful, anchor-consistent, and honest about completeness. Later refinement may reorder or retract lower-epistemic proposals but never erase provenance.

## 4. Candidate versus reference

An algorithm is admitted only after:

1. shared input/output contract;
2. differential corpus and adversarial families;
3. metamorphic relations;
4. cancellation and budget tests;
5. deterministic tie-break tests;
6. complexity witness and resource envelope;
7. same-binary A/A and A/B receipts;
8. fault and numerical-stability campaigns;
9. documented fallback and refusal.

## 5. Optimization order

Optimize measured walls in this order:

```text
better problem formulation
→ less redundant work through incremental reuse
→ better asymptotic algorithm
→ sparse/factorized representation
→ locality and allocation control
→ bounded parallelism
→ portable SIMD
→ GPU/process acceleration
```

No optimization may weaken evidence or replace semantic equivalence with visual plausibility.
