# Deep-Dive Method

Each sibling-project study asks:

1. What exact mechanism is load-bearing rather than merely analogous?
2. Which invariant does it establish?
3. Which FDGR abstraction level and crate owns it?
4. What superficial imitation would preserve vocabulary while losing semantics?
5. What deterministic reference or oracle is required?
6. What failure/trust boundary contains it?
7. What admission evidence must exist before the integration can be claimed?
8. Should FDGR depend on the sibling, reuse the design, or keep a replaceable seam?
9. How does the mechanism improve the agent operating loop or lower total control cost?

Studies are pinned to repository source identities and concrete files/symbols where available. README claims are treated as orientation; implementation, tests, registries, qualification artifacts, and explicit status boundaries carry greater weight.
